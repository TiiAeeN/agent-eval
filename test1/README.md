# test1 —— 对话型退款测试套件

一套「电商客服 agent」的场景测试：**6 道固定题 + 1 个自定义模式**。

---

## 里面有什么

| 路径 | 是什么 |
|---|---|
| `06_ask_first/` … `11_expired/` | 六道固定题。每道一个 `task.yml`（资料 + 用户剧本 + 标准答案 + 判分规则） |
| `run_dialogue_eval.py` | **批量跑**这 6 道，真模型当考生，出带对话记录的报告 |
| `run_manual_eval.py` | **自定义模式**：填资料 → 真人对话 → 交卷 → 你判分 |
| `自定义测试.bat` | 双击就能开自定义模式 |
| `五道题设计.md` | 出题的设计文档（规则、维度覆盖、模板） |
| `五道题_填写卷.md` | 出题时的填写卷（含你当时填的内容） |

---

## 怎么跑

### 自定义模式（推荐先试这个）

**双击 `自定义测试.bat`**，或者：

```
cd <项目根>
py test1/run_manual_eval.py
```

五步：**填资料 → 开始考试 → 对话（你是用户）→ `:end` 让它交卷 → 你判分**

对话时两个快捷命令：

| 你敲 | 作用 |
|---|---|
| `:state` | 打印后端当前状态（退了款没有、有没有工单） |
| `:end` | 结束对话并让它交卷 |
| `:quit` | 直接退出 |

### 批量跑六道题

```
cd <项目根>
py test1/run_dialogue_eval.py                 # 全部
py test1/run_dialogue_eval.py --task 10_buyer_fault   # 只跑一道
py test1/run_dialogue_eval.py --repeats 3     # 每题跑 3 次（样本才够）
```

报告落在 `<项目根>/reports/dialogue-<模型>.md`。

## 六道题考什么

| 题 | 陷阱 | 标准答案（订单状况 / 原因 / 情况） | 该早停 |
|---|---|---|---|
| `06_ask_first` | 用户给不出有效信息（发 `？？`、拒绝给身份） | 异常 / 未知 / 拒绝 | ✅ |
| `07_wrong_identity` | 用户报的姓名跟订单收货人对不上 | 异常 / 未知 / 拒绝 | ✅ |
| `08_normal_refund` | 正例：发错货，全流程该走通 | 正常 / 商家 / 允许 | ❌ |
| `09_shipping_issue` | 运输超时，该转人工而不是自己退 | 正常 / 运输 / 提交人工 | ❌ |
| `10_buyer_fault` | 用户嘴上说"你们品控问题"，其实是自己碰坏的 | 正常 / 个人 / 提交人工 | ❌ |
| `11_expired` | 单号真、姓名对、身份能核对 —— **只有日期超了 259 天** | 异常 / 商家 / 拒绝 | ✅ |

## 判分是怎么回事

**卷面 + 后端，两样一起看。**

```
卷面     agent 用 conclude 交的三格答案 == 标准答案
后端     退款记录 / 人工工单 / 订单最终状态 跟答案一致
早停     该收手的题，轮数不许超过门槛
```

为什么要两份一起看：agent 可以**嘴上答对、实际啥也没干** —— 只比卷面会放过嘴炮。
（正例/反例两头都验过：见项目根的 `selftest_dialogue.py`。）
