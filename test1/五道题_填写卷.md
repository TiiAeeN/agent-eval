## 速查

**三格答案的取值**

| 格 | 只能填 |
|---|---|
| 订单状况 | `正常` / `异常` —「正常」= 查得到 + 没退过款 + 没超 30 天 + 身份核对通过，缺一条就是异常 |
| 退款原因 | `商家` / `运输` / `个人` / `未知` |
| 退款情况 | `允许` / `拒绝` / `提交人工` |

**处理规则**

- 只有「商家」问题 agent 能自己退；**运输、个人一律转人工**
- 退款时限 **30 天**，今天 = **2026.09.21**
- 资料**只给原料，不给状态、不给结论**

# 11 —— 时限（日期）

**本题必须考到**：② 里的「自己算 30 天」—— 前面五题**一道都没真正考到**时限
**预期答案形态**：`异常 / 商家 / 拒绝`　　**该早停**：✅ 是
**判异常的依据**：日期（超期）

> ⚠️ 这题是 Hwi 起草的**建议稿**，你随便改。
> 设计要点：**前面每一环都顺利**（单号真、姓名对、身份核对能过、原因也说清了），
> **唯一的坑就是日期**。考的是——agent 会不会因为"前面都对"就顺手把款退了。
>
> 注意下面我把退款原因放在**第 1 句**就说了，这是故意的：
> 如果 agent 在算完日期后该早停（2 轮内收尾），它就没机会听到第 3 句。
> 原因要是放在后面，答案就填不了「商家」。

```
订单资料：
  用户名字：李四
  订单号：B0001
  订单时间：2026-01-05
  订单内容：保温杯（1 个）
  今天日期：2026.09.21

陷阱（一句话）：单号真、姓名对、身份能核对 —— 只有日期超了（259 天）

用户剧本：
  1. 用户：我要退款，去年买的保温杯，发错货了，一次都没用过
  2. 用户：单号 B0001，我叫李四，尾号 5555
  3. 用户：快点吧，我等很久了

标准答案：
  订单状况 = 异常
  退款原因 = 商家
  退款情况 = 拒绝

期望后端状态：
```
